# Work OpenSpec Dependency-Ready Batches

Use CLI artifactPaths, resolvedOutputPath, and changeRoot as layout authority. Read concrete existingOutputPaths and contextFiles, never guessed files. Required specs must contain non-empty <changeRoot>/specs/<capability>/spec.md files; an empty directory is not completion. Missing metadata blocks work.

Resolve an explicit change or an unambiguous existing change from context or `openspec list --json`; otherwise stop for selection. Never create a change. Run `openspec status --change "<change>" --json`; reject any schemaName other than `compound-intent-driven`. Honor planningHome, changeRoot, and actionContext. For a named store, discover its id with `openspec store list --json` and retain `--store <id>` on change commands.

Run `openspec instructions apply --change "<change>" --json`. Read every concrete dependency path or contextFiles entry, including proposal, specs, design, adr, and tasks, plus relevant code and learnings. Stop if apply is blocked or all_done. This invocation authorizes an outer apply loop over all dependency-ready tasks.md batches recorded in the approved plan; an explicit task selection narrows the envelope to that task. Derive readiness from current OpenSpec metadata, task dependencies, stable unit/batch IDs, and plan claims, never arbitrary unchecked tasks. Missing ownership, proofs, dependencies, or conflicting claims are blockers, not permission to infer a schedule.

Before each dispatch, refresh status/apply instructions and compare artifact contents and task claims with the approved envelope. Select only tasks whose dependencies have passing proof and authoritative completion. Dispatch at most 5 parallel workers with disjoint mutation paths and independent shared-state/test resources; use fewer than 3, including one, when fewer independent tasks exist. Serialize overlapping claims. Each worker receives one taskId, unit/batch/dependency layer, concrete context paths, settled decisions, named proof, allowed mutation paths, and stop criteria. Each worker performs exactly one task and returns the universal result packet; it never schedules another worker or chooses another task. If delegation is unavailable, execute the same one-task contract serially.

An outer controller may supply pre-created isolated worktrees with explicit task/path mappings. Verify distinct canonical roots, approved repository/baseline, no unrelated dirty changes in claimed paths, isolated test resources, and access to authoritative OpenSpec context before dispatch. Missing or failed isolation checks block dispatch. Neither this adapter nor its workers create, switch branches, merge, or delete worktrees; they do not commit or move changes between worktrees. Isolated worker results are pending until the outer controller makes changes available in the authoritative workspace and proofs pass there. Stop for that handoff rather than marking completion from an isolated copy. Worktrees do not bypass overlapping claims or dependency gates.

Use ce-work reasoning inside each worker. Preserve settled artifacts instead of re-asking plan/work scope. Establish targeted proof before behavior changes when feasible, implement only selected task, and run its named verification. Allow only task-owned implementation/test paths authorized by the packet; the coordinator alone owns the OpenSpec task checkbox within changeRoot. Mark that checkbox only after proof passes against the authoritative result and the coordinator checks exact mutations and unchanged task claims. Use ce-simplify-code only on settled changed code; skip mechanical/docs-only work. Preserve behavior, security, input validation, data-loss protection, and accessibility. Rerun affected proofs after simplification. Stop on scope/design conflicts.

After each batch, reconcile worker packets, run affected integration proofs, update only proven checkboxes, and refresh OpenSpec status/apply instructions before the next dependency layer. Continue within this approved apply envelope until all_done. Stop dispatch on any blocker, no-op, stale state, failed proof, conflicting mutation, or unfinished tasks with no ready batch; collect active workers safely and report partial evidence without promoting unproven tasks. Continuation is reconstructed from OpenSpec artifacts and refreshed metadata, never a CE-native queue, tracker, or persisted worker state. Do not run destructive or external-side-effect proofs; request safe local verification instead.

OpenSpec overrides conflicting CE skill instructions. No parallel CE plans/trackers, commits, branches, pushes, issues, PRs, automatic stage selection/advance, or archive. Do not run CE-native side effects. Workers stop after one task; the coordinator stops at the apply envelope boundary. No new workflow artifacts outside changeRoot; authorized task implementation/test paths remain the only implementation writes.

Refresh `openspec status --change "<change>" --json` even on a blocked handoff when possible. Return outcome, proof, mutations, blocker, and refreshed status in this universal result packet for every worker and the aggregate: Outcome (completed/blocked/no-op/stale); Change/Schema/Artifact-or-task/Batch/Worker/Dependency layer (explicit IDs, none if inapplicable); Proof (commands, results, failures and integration evidence); Mutations (exact paths and coordinator-owned checkboxes); OpenSpec state (refreshed status or unavailable); Continuation (remaining task/batch IDs and prerequisites, not a second tracker); Blocker (or none); Next command (one exact command, not executed). Workers return a safe status command for coordinator reconciliation, not a new assignment. The coordinator returns `/opsx-ce-review "<change>"` after proven all_done, `/opsx-ce-debug "<change>" "<task>"` for a mapped failure, or an exact status/instructions command for blocked/stale inspection. Use `none` plus the required decision when no command is safe. Substitute resolved values and retain named-store selection. Report unavailable CLI honestly; never install a runtime.
