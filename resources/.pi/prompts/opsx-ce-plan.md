# Plan One OpenSpec Artifact

CLI artifactPaths and resolvedOutputPath are layout authority; generates is relative to changeRoot. Expand specs/**/*.md into non-empty <changeRoot>/specs/<capability>/spec.md files for approved capabilities, never a literal glob or empty directory. Read concrete dependency files and verify contents plus refreshed existingOutputPaths and status before completion. Missing metadata blocks work; never guess paths.

Resolve an explicit change or an unambiguous existing change from context or `openspec list --json`; otherwise stop for selection. Never create a change. Run `openspec status --change "<change>" --json`; reject any schemaName other than `compound-intent-driven`. Honor planningHome, changeRoot, and actionContext. For a named store, discover its id with `openspec store list --json` and retain `--store <id>` on change commands.

Require one explicitly selected planning artifact: specs, design, adr, or tasks. Do not select a stage automatically. Require its status to be ready; blocked prerequisites or an already completed artifact require an explicit owning-artifact revision decision, not bypass. Run `openspec instructions <artifact> --change "<change>" --json`. Read its template, every concrete dependency path or contextFiles entry, and settled proposal/specs/design/ADR decisions. Build a packet containing artifactId, resolvedOutputPath, instruction, settled decisions, and allowed mutation paths. Missing paths or conflicts are blockers.

Use ce-plan reasoning for only that artifact. Preserve settled artifacts instead of re-asking plan/work scope. Specs and design require proposal; adr requires design; tasks requires specs and adr. Never skip gates. Retain stable U-IDs and named proofs. Write only owned OpenSpec output paths within changeRoot. For adr, report any needed repository-level ADR as a blocker for separately authorized work; never edit accepted ADRs. Do not implement.

For design, record stable U1, U2, ... implementation units without renumbering: requirement links, dependency IDs/layers, owned paths and shared seams, execution posture, named proof, and completion criteria. Define stable batch IDs, independent task claims, conflict/serialization rules, and continuation conditions. For tasks, map stable checkbox task IDs to those units and batches; carry dependency edges, allowed paths, proof-before-checkbox gates, and stop/resume criteria into the CLI-resolved tasks.md. Dependencies and claims must be concrete enough to schedule without choosing arbitrary unchecked tasks. Missing or conflicting plan claims block the artifact; do not invent a second scheduler file or tracker. Specs retain concrete capability outputs and OpenSpec delta syntax; adr records only durable decisions in its change-local manifest.

OpenSpec overrides conflicting CE skill instructions. No parallel CE plans/trackers, commits, branches, pushes, issues, PRs, automatic stage selection/advance, or archive. No adapter-managed worktrees or external side effects. Do not run CE-native side effects. Stop after this artifact.

Refresh `openspec status --change "<change>" --json` even on a blocked handoff when possible. Stop on blockers, no-op, or stale state; never retry unchanged inputs. Return outcome, proof, mutations, blocker, and refreshed status in this universal result packet: Outcome (completed/blocked/no-op/stale); Change/Schema/Artifact-or-task/Batch/Worker/Dependency layer (explicit values, none if inapplicable); Proof (evidence and gate checks); Mutations (exact paths); OpenSpec state (refreshed status or unavailable); Continuation (remaining scope and prerequisites); Blocker (or none); Next command (one exact command, not executed). Honor an explicitly recorded continuation only after checking current CLI readiness; otherwise return `openspec status --change "<change>" --json` for inspection and request explicit artifact selection. Never choose the next planning artifact. Substitute resolved values and retain named-store selection; use `none` plus the required decision when no command is safe. Report unavailable CLI honestly; never install a runtime.
