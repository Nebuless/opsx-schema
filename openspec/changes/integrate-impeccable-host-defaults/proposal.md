## Why

The schema calls Impeccable its default method but does not require installation,
OmO is missing as a distinct host, and Pi routing assumes only a legacy adapter.
The approved installer behavior must reach the current public codebase without
replacing its newer CLI, provenance, and recovery implementation.

## Scope

Require Impeccable for intent-driven-design installation and selection, acquire
reviewed immutable skill revisions, add native OmO destinations, and distinguish
native Pi from verified existing legacy adapters. Preserve exact preview/Apply
and interactive MCP approval boundaries.

## Exclusions

Automatic hooks, helper-agent registration, adapter installation or migration,
implicit MCP configuration, unrelated local history, and merging the remote PR.

## Capabilities

### New Capabilities

- `impeccable-host-installation`: required schema skills and evidence-based native
  host routing with reproducible sources and guarded installation.

## Selected Direction

Port the approved behavior through existing domain operations and current modular
CLI handlers. Only Inspo and UI Skills MCP additions remain optional.

## Impact

Resource declarations, schema install/switch, skill source acquisition, MCP host
inspection, behavioral and package-consumer tests, and user-facing guidance.
No new dependency or service is introduced. Codex reviews and Macroscope feedback
must be resolved before reporting the published PR merge-ready.
