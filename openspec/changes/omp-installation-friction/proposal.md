## Why

[Issue #5](https://github.com/Nebuless/opsx-schema/issues/5) reports successful OMP installation after repeated blocked previews and manual recovery. Bundle diagnostic taxonomy, pre-install inspection guidance, ambiguous install grammar, unmanaged skill recovery, and legacy verification explanations made a correct guarded workflow hard to navigate. Existing ownership and provenance protections must remain intact.

## Scope

Improve schema-declared bundle diagnostics, project-resolution hints, install help, component-aware verification guidance, and end-to-end OMP instructions. Add an explicitly selected, preview/token-authorized collision replacement workflow that preserves verified backups and truthful recovery evidence. User selected this expanded route after discovery and approved its single-target direction for planning; completed implementation evidence is recorded in `tasks.md`.

## Exclusions

No unconditional force-overwrite, automatic adoption based on names or equal bytes, replacement of modified owned skills, silent bundle substitution, packaged tier duplication, project-to-bundled fallback, filesystem-source schema installer, invented historical provenance, changed warning/exit policy, MCP installation, runtime-version policy changes, publication or unrelated GitHub writes. External backup EXDEV, unsupported OMP RPC and Backlog wrapper failures are not installer defects.

## What Changes

- Unsupported skill bundle errors identify bundles separately from named agent profiles and show actual declared tiers. Compound's default includes all 11 declared skills; all is not universal shorthand.
- Project inspection of an uninstalled packaged schema receives actionable catalog/install guidance without changing OpenSpec resolution authority or hiding other failures.
- Install help names a bundled schema argument; examples use one project option and fresh tokens for every mutation.
- Explicitly reviewed unmanaged skill collisions can be backed up, verified and replaced through a guarded workflow. Ordinary install and schema switch still refuse unselected collisions; unrelated skills and active pins remain protected. Failed or interrupted operations expose exact backup, target and ownership state with safe recovery, not false success.
- Legacy verification explains which component failed and distinguishes unknown origin from damaged installation. Reviewed current revision/selection reconciliation never asserts a historical creation revision. Adapter checks remain separate.
- OMP instructions cover schema assets, skills, activation, adapters and actual native discovery as distinct stages.

## Capabilities

### New Capabilities

- `guarded-skill-collision-replacement`: exact reviewed target selection, no-clobber verified backup/replacement, ownership finalization, and recoverable partial-state evidence for unmanaged skill collisions.

### Modified Capabilities

- `project-and-agent-cli`: bundle-specific diagnostics, actionable project schema lookup guidance, unambiguous bundled-name help, explicit guarded skill collision operation, and component-aware verification guidance.
- `schema-resources-and-profiles`: active pin/association mutations coordinate with separately authorized resource replacement; ordinary refusal and retention remain unchanged.
- `workflow-validation`: make unknown historical provenance's existing blocking policy explicit without downgrading integrity or readiness failures.

## Selected Direction

User selected OMP5-GUARDED-REPLACEMENT on 2026-09-29 and then approved a separate resource-only, single-target operation followed by the existing fresh schema-switch preview, rather than broad replacement permission inside schema activation. Transaction details belong in design; that planning approval alone did not authorize production edits. Delivery authorization is recorded in `journey.md`.

CLI/resource/switch/provenance tests, affected durable specifications, command/workflow guides and changelog need updates after approval. No dependency or bundled skill-content change expected.

Keep the extracted module layout; do not restore obsolete modules or treat refactor approval as replacement approval. User authorized commits and issue #5 PR delivery on 2026-09-30, not npm release.
