## Context

Issue #5 installed the bundled compound schema, 11 OMP skills and nine adapters only after misread bundle/install grammar and manual preservation of five unmanaged skill directories. Existing refusal is correct: `src/resources/index.ts` treats unowned targets as collisions, including equal bytes; `src/switch/index.ts` blocks the full selected switch. The published probe and current code show `PROFILE_UNDECLARED` also labels missing skill bundles, and aggregate verification blocks an older change's `PROVENANCE_UNKNOWN` independently of finding severity. `journey.md` records probes, exclusions and two approvals. The four delta capabilities define observable behavior. ADRs 0001–0003 retain OpenSpec authority, immutable historical provenance and project-locked recoverable writes.

Current `src/resources/index.ts` uses `.openspec/opsx-schema/resources.lock` for resource mutation. Switch uses `openspec/.opsx-switch.lock` then enters the resource operation; create, handoff, archive and selection reconciliation can alter pin requirements outside that lock. A replacement holding only the resource lock cannot prove an active pin remains safe. Current CLI commands have been extracted into `src/domain/cli/commands/`; source references in investigation to the published monolith are evidence only.

## Goals / Non-Goals

**Goals:** Distinguish bundle/profile errors; make pre-install and multi-stage OMP commands accurate; explain failed legacy verification without changing its exit; supply an exact, independently authorized, recoverable replacement for one unmanaged skill tree. Keep target, backup, ownership and current pin state consistent across interruption and concurrency.

**Non-Goals:** Force/adopt, replacing managed drift, automatic `all` tier, implicit project-to-bundled resolution, automatic schema activation/adapters/MCP installation, relaxing provenance failures, invented creation history, OpenSpec lifecycle duplication, or multi-target atomic replacement.

## Selected Direction

1. Keep `skills install` and `schema switch` collision behavior. Add `skills replace <project-relative-target> --schema <installed-name> --bundle <declared-tier> --backup-id <unique-id> [--apply-token <token>]`; one exact real unmanaged skill directory per request. Resolve its source against verified installed schema manifest, host contracts and agent-profile manifest, not user-supplied source paths. Require a single matching declaration; show every profile/host sharing the physical target and reject source disagreement or physical host-root alias ambiguity. A caller repeats the transaction for other collisions, then starts a fresh ordinary full-set switch. `skills inspect` stays read-only, including unavailable tiers.
2. Use a caller-provided safe backup ID to derive a stable internal project backup/receipt path across preview and Apply processes; no generated ID in the token computation. Preview binds normalized exact target, source/manifest identity, complete old/source digests and filesystem identity, ownership bytes, active pin guard, backup absence and a deterministic file inventory/diff to the existing token contract. Include modes/digests for added, removed and changed files; decode text safely for a bounded diff, label binary and disclosed truncation. Explicitly refuse paths with traversal, symlinks, special entries, unsafe parents, same-name ambiguity or target roots. A digest-equal unmanaged tree still needs explicit replacement; edited managed content is never eligible.
3. Establish one project mutation lock protocol across switch, Opsx-controlled pin/association writers (create, handoff, archive, reconciliation), replacement and restoration. Operations needing both take project lock then resource lock; avoid nested reacquisition. Under both held locks, re-derive preview state and `requiredSkillTargets` with `verifiedPinOptions`, compare token/freshness and reject incomplete or target-intersecting active-pin knowledge. Check incomplete switch/replacement recovery affecting target before mutation. Standalone OpenSpec commands and external editors do not honor these locks: recheck the authoritative active-change inventory, pin/selection bytes, target identity and ownership at read/write boundaries; observed external drift refuses or becomes explicit partial state. Such checks cannot make a non-cooperating writer's change atomic with the swap; do not claim universal race freedom. This is narrow serialization around Opsx calls to OpenSpec, not a second authority for change state.
4. Record versioned receipt intent durably before altering the target. Reserve backup ID exclusively under contained, symlink-free `.openspec/opsx-schema` storage; copy existing directory (not cross-device rename) and verify its full digest. Stage declared source in a unique sibling of target, verify digest. Recheck original target and ownership, rename original to a unique same-parent rollback location, then rename stage into place; verify installed tree before an atomic expected-bytes ownership update. Flush each durable receipt phase and containing directory; receipt tracks exact before/after ownership, target identities/digests, source, backup, staged/rollback paths and error evidence. Mark complete only after target/ownership/receipt consistency. Keep backup and receipt indefinitely. State writes must never indicate completion before durable ownership.
5. If copy or staging fails, leave original untouched and preserve/identify safe partial files. If swap, ownership or receipt fails, restore only where present target and ownership still equal transaction-recorded states and complete active-pin proof shows the target unrequired; otherwise retain backup and every candidate tree, mark partial with exact observations, and block overlapping replacement until reviewed. Read-only `skills replace inspect <backup-id>` (or an equivalent exact-receipt subcommand chosen during CLI integration) shows recovery state. `skills restore <backup-id>` is a separate fresh preview/token mutation; require unchanged managed target, matching recorded ownership, verified backup and complete current pin guard under the same locks at both preview and Apply. A pin created after replacement prevents restoration. If anything drifted, refuse with manual recovery evidence; never overwrite external edits or alter OpenSpec provenance. Keep receipt/backups after restoration.
6. Presentation changes use existing CLI JSON v1 envelope and real operation results. Resource bundle diagnostics use a bundle-specific code with supported declared tier names; named agent-profile errors retain `PROFILE_UNDECLARED`. Project `skills inspect` offers bundled discovery/install hint only on a proven missing packaged schema, never on general OpenSpec failure. Rename schema-install help placeholder to `<bundled-schema-name>` without parser change. Aggregate verification retains nonzero failure; identify failed active-change component and note that adapters require separate inspect. Document exact-revision `skills reconcile` constraints, unknown creation, and OMP stage-by-stage preview/token commands.

## Implementation Guardrails

- Reuse `src/resources/index.ts` containment, `stateAt`, `digestTree`, source validation, ownership compare/write, and resource lock primitives; extract narrowly where needed. Project lock must be shared by all pin writers and switch. Pin/ownership reads for preview alone cannot authorize Apply. Do not take project lock after resource lock or hold it while waiting for user approval.
- `--backup-id` is a single validated safe component. Exclusive directory creation prevents reuse; no deletion of unrelated trees. Capture original device/inode and metadata plus content digest, but do not treat inode/digest as sufficient against adversarial external filesystem races. Follow contained path `lstat` and exact pre-write rechecks; report residual race limits. Old content must be recoverable even when backup and skill reside on different devices.
- Receipt parser rejects malformed, unsupported-version, escaping or symlinked records; durable writes use exclusive/temporary files plus sync. A crash at every phase must be inspectable; recovery never assumes the final receipt persisted if a previous write failed. Avoid spurious one-size-fits-all rollback; compare exact transaction-owned state before each reversal.
- No new dependency for diff or transaction engine if existing Bun/Node primitives suffice. Limit preview bytes without dropping changed-file inventory; disallow silent text decoding of binary content. Existing narrow CLI, resource, switch, provenance and validation modules own behavior; avoid parallel semantics in TUI. Keep OMP's native discovery proof separate from checking installed paths.
- Test consumer-visible state at failure boundaries: cross-device copy, duplicate ID, stale source/target/ownership/pin, lock order and concurrent pin writer, backup/stage/swap/metadata/receipt failures, partial recovery, safe restore and external-edit refusal, shared aliases, text/binary/truncated diff, JSON/nonzero presentation. Exercise actual CLI preview/Apply and restore on a disposable project after code changes; the current plan does not authorize those edits.

## Alternatives Considered

- Documentation-only manual backup: less code and coordination but user selected a guarded operation after recovery friction; retain manual instructions as fallback for partial states.
- `--force` within schema switch or all-collision batch: couples irreversible unowned replacement to default/pin activation and greatly expands rollback surface. Rejected in favor of one reviewed resource target per transaction.
- Treat equal bytes as owned or add duplicate `all` bundle: fabricates ownership or tier declaration. Rejected.
- Resource lock alone or separate replacement lock: does not serialize pin writers. A shared project-first lock and under-lock pin recheck are required.
- Rename old target directly to internal backup: can fail across devices (`EXDEV`) and removes unowned data before a verified backup. Copy/verify then same-parent swap keeps a recoverable original.
- Reclassify `PROVENANCE_UNKNOWN` warning as nonblocking: changes lifecycle policy and risks hiding missing history; explain component failure instead.

## Risks / Trade-offs

- Broad lock coordination changes create/handoff/archive/switch paths. A skipped writer recreates a pin race; inventory each writer, lock-order test, preserve existing rollback behavior, and refuse when pin knowledge incomplete.
- Disk usage increases by old backup, staged source and temporarily retained rollback tree. Do not silently garbage-collect user data; document capacity and explicit inspection. Backup I/O adds latency only for explicitly requested replacement.
- Crash plus external edits may make automatic rollback impossible. Durable phase receipt and exact-state refusal preserve data instead of claiming success; instructions name affected paths and safe manual recovery.
- Shared host/profile destinations may conceal multiple consumers. Show all aliases; refuse conflicting source mapping. Normal full-set preview remains necessary after each replacement.

## Migration Plan

No automatic migration of existing skills, ownership, active pins, or historical provenance. Add read/preview capability first; gate replacement Apply behind coordinated writers and recovery handling, then expose command/docs. Existing unowned directories remain unowned until explicit backup/token Apply. Existing switch journals stay under their current contract; new receipts are distinct and versioned. On rollback of a release, preserved backups/receipts remain inspectable from project files rather than auto-deleted. Specs, CLI guide, workflow guide and changelog are updated with implementation, then targeted test and disposable CLI proof, distribution smoke, strict change validation and full pre-PR check if shipping requested.
