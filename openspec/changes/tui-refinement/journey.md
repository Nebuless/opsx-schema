# Design Journey

## Scope and Exclusions

- Scope: Refine progress and read-only document inspection within the approved Change Register identity. Task progress leads; planning remains independent. Keep compact status and file identity visible above Document / Source / Diff reading modes in Changes and Archive.
- Exclusions: No replacement visual world, new dashboard tabs, lifecycle authority, document editing, interactive checklist writes, Settings redesign, new dependencies, registry installations, provider configuration, release work, or alteration of the completed tui-change-register artifacts.
- This request authorizes planning only. Implementation requires a new apply request.

## Material Decisions

- D1: Exact checked/total task counts and remaining work lead progress; planning counts are secondary. Unknown or invalid totals have no bar. Known zero-task results have a no-tasks label, not a percentage. Incomplete progress must never fill the final bar cell or say 100%.
- D2: Retain a large reader with a compact change-status header and breadcrumb. Do not add a file-list sidebar. Preserve filtered list selection and Esc return behavior.
- D3: Markdown files open in readable Document mode with Source and separate Git Diff modes. Source is the existing sanitized, bounded text preview, not a promise of raw bytes or full-file access. Non-Markdown files remain Source with Diff available.
- D4: Use existing OpenTUI Markdown and diff renderers, shared theme, trusted reads, and browser keyboard ownership. TermCN/TUI Parts inform component presentation; they are not wholesale dependency adoption.
- D5: Archive shows historical status and retained checklist counts. Retained planning files do not establish historical artifact readiness. Checkboxes remain passive document content.
- D6: At 60x18, shorten context and keep secondary metadata reachable in detail; preserve document space, current mode, and back/actions. Respect NO_COLOR and reduced motion.
