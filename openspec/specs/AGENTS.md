# openspec/specs

## Purpose

Durable capability specifications shared by OpenSpec changes.

## Ownership

Capability directories own their `spec.md`; this directory owns no capability semantics itself. `.gitkeep` preserves empty-state layout.

## Local Contracts

- Requirements use SHALL/MUST wording and scenarios use parser-compatible GIVEN/WHEN/THEN structure.
- Modified requirements retain complete existing blocks before edits.
- Specs remain observable and testable.

## Work Guidance

Read selected change artifacts and existing capability spec before modifying a capability.

## Verification

Use strict OpenSpec validation for the selected schema and change.

## Child DOX Index

No child DOX files. Capability directories are dynamic leaves.
